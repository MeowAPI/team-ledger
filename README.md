# 一起记 · 小团队共同账本

[![Docker build](https://github.com/MeowAPI/team-ledger/actions/workflows/docker-publish.yml/badge.svg)](https://github.com/MeowAPI/team-ledger/actions/workflows/docker-publish.yml)

供扁平化小团队使用的 Web + Telegram 记账系统。每位成员都有独立账号，拥有相同的管理权限。记账后直接待报销，付款后标记已报销，无需审核，没有分类功能。

## 已实现

- Web 表单记账，以及 Web / Telegram 的 AI 自然语言记账助手：一次可说一段话，拆成多笔新增 / 修改 / 作废 / 报销 / 盈余分红 / 查询，核对清单后执行。
- 成员垫付、团队收入 / 资金分红（待报销未结清也可分红）、多币种、日期、备注、PNG / JPG / PDF 凭证。
- 记录谁垫付；草稿、待报销（含部分报销）、已报销、作废，以及逐笔操作记录。
- 未付款支出可修改，支持逐笔或批量填写本次报销金额，允许分次报销；重复请求不会重复入账或扣款。
- 记账用途 / 收入说明、备注均选填，留空也可保存草稿或入账；列表中的空说明显示为“未填写说明”，原始记录与导出保留空值。
- Telegram 按钮记账：选择币种 → 输入金额 → 预览确认。预览中可选填用途、备注，并修改金额、币种、日期和成员；编辑用途或备注时发送 `-` 清空，升级前停在用途步骤的草稿也可发送 `-` 跳过。付款参考号、作废原因和分红说明不受此规则影响。
- Telegram AI 自然语言记账：私聊或 `/ai` 一次说一段话，生成可逐项勾选的操作清单；确认后才入账。
- Web / Telegram 资金计算支持模拟新增收入、指定报销预算或勾选项目、查看余额 / 结余 / 缺口；Telegram 可按本次安排及实际余额一键登记报销。
- Telegram 菜单支持个人 / 团队待报销、最近账目分页、今日 / 本月收支、余额与具体付款项目。
- Telegram 可修改未付款支出，填写备注并二次确认后登记付款或作废；会检查并发修改和重复操作。
- 可配置币种、默认记账币种、资金汇总参考币种。
- 自动查询公开汇率 API，计算今日收入、累计可用资金、可预留报销、可安排付款、结余与缺口。
- 导出带 UTF-8 BOM 的 CSV，金额和币种分列；导出文本做了公式注入防护。
- SQLite 持久化；不需要 Redis、PostgreSQL、Node 或前端构建工具。

## 本地启动

需要 Python 3.12 或更新版本。Windows PowerShell 中进入项目目录：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python run.py
```

打开 **http://127.0.0.1:8765**，创建第一个团队账号。之后任何成员都可以在「团队成员」创建新账号。

首次启动没有预设账号、密码或示例账目。密码至少 10 位。所有已启用成员均可管理成员、重置密码、修改设置、登记收入和报销付款，符合扁平团队的共同管理方式。系统会阻止停用最后一个可用账号。

原有环境已安装依赖时，直接 `python run.py` 即可。

## 账务规则

1. 成员支出是个人垫付。记账后直接进入待报销，不会直接扣减团队资金。
2. 团队收入增加资金；分红独立登记，以扣除已报销、历史分红后的实际可用余额为上限，待报销未结清也可分红；**实际转账后登记本次已报销金额**，按真实付款币种与金额扣减资金，支持分次付款。
3. 草稿、已作废支出不进入待报销；已作废收入不增加资金。
4. 新增 / 记错的未付款账目可以填写原因作废。已有任何报销记录的支出不能作废。未结清时仍留在待报销列表，全部结清后不能继续付款。已作废账目默认不出现在收支明细、总览和最近账目，可在报销管理的「已作废」标签或 Telegram 已作废列表中查看；确认后可永久删除，账目、操作记录、付款记录和凭证会一并清除，无法恢复。
5. 没有付款记录的草稿和待报销支出可以修改；部分或全部报销后锁定账目编辑，防止修改金额、币种或垫付成员破坏历史。全部历史操作和逐次付款记录可查看。
6. 每笔记录保留原始币种与金额，金额按货币最小单位以整数存储。日元默认 0 位，人民币 / 美元默认 2 位。
7. 所有成员都可直接登记报销付款，不需要其他成员批准，操作人和付款备注会被记录。

旧版本升级时，待审核与已审核未付款支出自动迁移为待报销，已驳回支出回到草稿。金额、原币种、已付款记录和历史操作记录保留。

## 资金如何计算

统一以设置中的参考币种换算：

```text
可用资金 = 团队收入 − 已报销付款 − 已分红
全部待报销 = 所有待报销支出的未报销余额
本次报销范围 = 全部待报销，或手动勾选项目的未报销余额
本次安排报销 = min(max(可用资金, 0), 本次报销范围, 本次报销预算)
安排后结余 = 可用资金 − 本次安排报销
安排后仍待报销 = 全部待报销 − 本次安排报销
资金缺口 = max(全部待报销 − max(可用资金, 0), 0)
可安排付款 = 本次安排报销
```

例如：收到 1,000 USD，参考汇率为 1 USD = 7 CNY（仅示例），团队当前待报销 3,000 CNY、没有之前的收入和报销付款，则预留 3,000 CNY，结余 4,000 CNY。

「资金计算」默认按最早发生日期自动安排全部待报销，可切换为「指定报销预算」或「手动选择报销项目」。未指定预算时不额外限额；预算采用当前汇总参考币种，可填 0 暂不安排报销。手动模式仅安排勾选项目，不勾选则不安排任何项目。未安排和未结清的余额继续待报销；这些选择只用于本次计算，不会修改账目或自动付款。

可模拟一笔**尚未入账的新收入**，在当前余额上加上该金额，计算资金安排。Web 新增进账留空时直接安排当前余额。模拟不会生成真实收入，也不会提高实际分红上限。已经登记的收入不要再输入一次模拟，否则会重复计入预演。

所选范围内优先安排发生日期最早的记录。预算或余额不足时显示某笔的部分安排；实际付款后，可在 Web 或 Telegram 填写本次已报销金额，剩余部分继续待报销。

「资金计算」的伙伴报销安排会展开到具体项目，显示项目用途、原币种金额、结算参考金额和该项目的建议付款金额；如果余额不足，会标记为部分安排或暂不安排。

汇总采用本次报告获取 / 缓存的参考汇率，对历史原币种金额重新换算；它是资金规划参考，**不是锁定的历史记账汇率，也不是实际银行结算金额或会计利润**。没有实际换汇的不同币种资金，能否在付款时使用，由团队自行确认。系统不会执行转账。

## 部分报销与付款币种

Web 在账目详情或报销管理中点击「登记已付款」，逐笔填写**本次**实际付款金额；金额不是累计值。每笔可以选择记账货币，或团队设置的结算货币（汇总参考币种）。待报销列表包含部分报销，详情、付款建议、成员汇总与 CSV 均显示已报销和剩余款。

例如记账 100 USD，结算货币为 HKD，确认时参考汇率为 1 USD = 7.80 HKD：本次实际支付 312 HKD，抵扣 40 USD，累计已报 40 USD、剩余 60 USD；下一次也可改用 USD 报销。每次保留实际付款金额 / 币种、抵扣的原币金额、操作人、时间、备注和汇率快照。资金余额按实际付款扣款，不会把 312 HKD 当作 312 USD，也不会对已确认的付款重新折算抵扣额。

跨币种确认换算有效 30 分钟；结算货币采用服务器取得的每日参考汇率，汇率不可用时可继续按记账货币登记。按币种最小单位四舍五入，填写「剩余全额」对应金额会结清原账剩余，避免尾差。界面中的后续参考换算会随每日汇率变化，历史付款和已抵扣的记账金额保持不变。该汇率用于报销抵扣，并非银行实际换汇成交价。

旧版已全额报销的账目自动生成一次历史付款明细，保留原日期、备注和金额；迁移可重复执行，不会重复扣款。

## 资金分红

分红依据账本的**实际可用余额**，不与某笔收入关联，待报销未结清也可登记：

```text
团队余额 = 收入 − 已报销 − 已分红
可分红金额 = max(团队余额, 0)
```

例如收入 1,000、已报销 400、待报销 800，最多可分红 600；本次分红 200 后，团队余额 400、待报销仍为 800，还可分红 400。待报销款不强制预留；分红会减少后续可报销资金，团队自行决定报销与分红的安排。

Web 进入「盈余分红」，点击「填写本次已分红金额」或「全部可分红盈余已分红」。选择实际转账币种并填写说明，核对金额后确认。Telegram 发送 `/dividends` 或从菜单进入「盈余分红」，同样支持手动金额、全部盈余、币种选择和分页历史。

金额是本次增量，不是累计金额。分红独立保存金额、实际币种、操作人、说明、时间和参考汇率快照；收入和报销账目不改变，导出 CSV 包含独立分红行。实际换汇和转账由团队完成，系统只登记。跨币种上限向下取整到付款货币最小单位，保留不足最小单位的尾差，不会超出盈余。

确认有效 30 分钟；账目、报销、其他分红或结算设置改变时需重算。重复请求不重复扣款，同一确认只能生成一笔记录。模拟收入不参与实际分红，分红不会核销或清空待报销项目。

已移除按收入标记已分红的旧规则。升级时旧标记自动转换成等额独立分红记录，原收入恢复正常入账；原币种现金净额不变，历史操作和凭证保留，重复升级不重复生成分红。

## Telegram 资金计算与一键报销

打开菜单「资金与付款项目」或发送 `/funds`，查看资金、待报销、建议预留、结余、缺口和具体项目。点击「模拟新进账」选择币种并输入金额，只试算，不写入账本；需要记录真实进账时，点击相应按钮后核对收入预览并保存。

点击「设置报销预算」填写本次使用的结算币种金额，或点击「选择报销项目」分页勾选；可点「恢复自动安排」取消本次限制。「按实际余额一键报销」沿用本次预算或所选项目，始终使用已入账的真实资金，排除模拟进账，并扣除已登记分红。选择「按结算货币」或「按各笔记账货币」，机器人按最早发生日期生成逐笔清单；预算或余额不足时，只安排能覆盖的部分。每笔列出项目、成员、实际付款、抵扣记账金额及剩余待报，支持翻页、填写批次付款备注。

完成真实转账并核对清单后，点击「确认已转账，一键登记」一次保存全部付款。账本或结算设置变化、确认 / 汇率快照过期时整批拒绝，需重新计算；重复点击不重复扣款，剩余部分继续待报销。机器人只记录付款，不执行银行 / 链上转账。原币种转账之间是否已实际换汇，仍由团队确认。

## 汇率 API

默认使用 [Frankfurter](https://frankfurter.dev/) 的公开接口，无需 API Key：

```dotenv
FX_API_URL=https://api.frankfurter.app/latest
FX_CACHE_HOURS=12
```

兼容 v1 的 `base/date/rates` 返回格式，也支持 `https://api.frankfurter.dev/v2/rates` 的数组格式。数据为每日参考汇率，周末 / 节假日可能返回最近工作日，界面会显示每对汇率的来源与日期。

- 同币种计算不访问汇率服务。
- 接口失败且有缓存时，明确提示缓存和日期。
- 某币种缺少汇率且没有缓存时，暂停合并计算；原币种账目仍可查看和记录。
- 只有服务商支持的币种才能自动换算。自行增加币种不会保证 API 一定支持它。
- 缓存与原始账目一起保存在 SQLite。

## 配置 AI：Web 和 Telegram 共用

在 `.env` 填写你拥有的 OpenAI 兼容 Chat Completions 服务，然后重启 Web / bot：

```dotenv
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=填写你的密钥
AI_MODEL=填写接口实际支持的模型名称
AI_RESPONSE_FORMAT=json_object
```

`AI_BASE_URL` 不要包含 `/chat/completions`，程序会追加它。兼容结构化输出的服务可设置 `AI_RESPONSE_FORMAT=json_schema`；默认 `json_object` 要求服务支持 JSON 输出模式。

支持一次说一段话，AI 会拆成多条可核对的操作：

```text
昨天我垫了打车 35 元，老王垫的聚餐 240 元，收到客户尾款 2000 美元；
把上周那笔重复的 #18 作废；老王所有待报销都报掉；
顺便告诉我这个月花了多少、现在还能报多少。
```

覆盖的记账能力：

- 批量新增成员垫付 / 团队收入，支持草稿、指定垫付成员、日期、币种、备注；收入统一记为团队在账。
- 修改尚未报销的草稿或待报销支出；作废账目；草稿记入账本；登记资金分红。
- 单笔部分 / 全额报销，按记账货币或团队结算货币；按可用资金、指定成员、项目或总预算批量登记报销。总预算采用团队结算币种，可与项目筛选组合。
- 永久删除已作废账目（会清除账目、操作记录、付款记录和凭证，无法恢复）。
- 只读查询：明细、统计、余额、待报销、资金规划、模拟进账、单笔详情、分红记录。查询会直接回答，不需要确认。

安全规则：

- AI 只生成**待确认操作清单**，不会直接写入。你可以在 Web 勾选 / 取消每一项，或点「在表单中修改」补充凭证；Telegram 中可逐项勾选后一次确认。
- 确认时会在一个事务里重新校验金额、币种、日期、账目版本和付款报价；任一项已变化则整批不写入。
- `pay_entry` / `batch_pay` / `dividend` 只登记**已经实际完成**的转账，不会发起付款。分红以扣除已报销、历史分红后的实际可用余额为限，待报销未结清也可登记；必须排在本次清单的其他写操作之前，否则 AI 会提示先确认前面的操作。
- 一次最多 20 个动作、约 120 笔账目上下文；操作清单 30 分钟内有效。超过限制或描述有歧义时，AI 会先追问，不会猜测。
- 交易记录、账目描述和历史对话都只作为数据，不执行其中的指令。
- 支持追问：Web 助手保留当前对话上下文，可以直接说「把第二笔改成 50」；Telegram 在清单确认前继续发消息，会带着上一版清单重新整理。已执行的清单不会重复执行。

发送给 AI 接口的内容：**当前输入、最近账目摘要（编号、日期、类型、金额、币种、用途、备注摘要、成员、状态、剩余/已报销金额）、资金概况（含已分红与可分红盈余）、成员姓名、币种配置、当前日期/时区、最近几轮对话**。不会发送凭证文件、密码、会话令牌或 Telegram 绑定信息。可用 `AI_CONTEXT_ENTRIES` 调小上下文条数（最小 20）。密钥仅在服务端使用，不通过配置 API 返回到浏览器。

可选配置：

```dotenv
AI_TIMEOUT=40              # 单次模型调用超时秒数
AI_CONTEXT_ENTRIES=120     # 发送给模型的最近账目条数（会优先保留可操作账目）
AI_CONTEXT_CHARS=60000     # 上下文 JSON 的字符上限
AI_MAX_ACTIONS=20          # 单次最多生成的操作数
```

未配置密钥或模型时会给出提示，表单和按钮方式正常工作。当前不支持发票 OCR、语音输入；凭证需在 Web 账目详情或新建表单中上传。成员账号、密码和团队设置不通过 AI 修改。

接口实现参考 [OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat)。不同兼容服务的模型和 JSON 模式支持可能不同，需使用该服务实际提供的配置。

## 接入 Telegram

1. 在 Telegram 的 BotFather 创建机器人，取得 Token。
2. 在 `.env` 设置 `TELEGRAM_BOT_TOKEN`。
3. 保持 Web 运行，另开终端，在同一项目目录启动：

```powershell
.\.venv\Scripts\python -m app.bot
```

4. 每位成员登录 Web →「机器人与 AI」→ 生成绑定码。
5. 在机器人的**私聊**发送 `/start 绑定码`。绑定码 10 分钟有效，使用后立即失效。
6. 发送 `/start` 查看按钮菜单，`/book` 记录垫付，`/income` 记录收入。

命令：

| 命令 | 用途 |
| --- | --- |
| `/start` | 展示记账按钮菜单 |
| `/book` | 逐步记录一笔成员垫付 |
| `/income` | 逐步记录一笔团队收入 |
| `/ai 今天打车花了35元` | AI 识别；也可一次描述多笔、修改、作废、报销或查询，核对清单后入账 |
| `/summary` | 查看自己的待报销，按原币种列示 |
| `/recent` | 分页查看最近账目（默认不含已作废），点项目打开详情；可进入已作废列表永久删除 |
| `/team` | 分页查看团队待报销明细 |
| `/funds` | 查看余额、结余、资金缺口与建议付款的具体项目 |
| `/today` | 今日收入与成员垫付，按原币种分别列示 |
| `/month` | 本月收入与成员垫付，按原币种分别列示 |
| `/cancel` | 取消当前草稿 |
| `/help` | 使用提示 |

私聊直接发送自然语言也可触发 AI。正在填写按钮表单时，普通文字会用于当前金额 / 用途步骤；用 `/cancel` 清空或 `/ai ...` 另起识别。

默认只允许已绑定账号的私聊。要在群组中使用，在 Web「团队设置」添加群组 ID（如 `-100...`），群内每个使用者仍需先私聊绑定。不要把绑定码发到群里。群中用命令 `/book`、`/ai ...` 或按钮开始；填写金额、用途、付款备注等信息时，**回复机器人发给你的输入提示**。机器人会验证回复归属和当前步骤，普通群聊不会触发 AI 或填入草稿。话题群中的回复保留在原话题。

主菜单入口为 `/start`。列表支持上一页 / 下一页，按钮切换尽量编辑原消息减少刷屏。每笔账目可显示原币种及每日参考汇率换算金额。草稿和操作确认码均绑定当前成员，过期或重复确认不能重复入账 / 付款。已入账支出若同时被 Web 修改，机器人会要求重新核对再保存。

在待报销详情点「登记已付款 / 继续报销」，选择「按记账货币」或「按结算货币」，填写本次实际已报销金额（发送 `全额` 结清剩余），再填写付款方式 / 参考号。确认页展示实际付款、抵扣的记账金额、累计已报和剩余待报，确认后才登记。金额或币种填错可在确认页重新选择；群聊中仍需回复对应提示。所有成员都可操作，凭证在 Web 上传和查看，机器人不会发起真实转账。

机器人采用长轮询，不需要公网 Webhook，但服务器必须能访问 Telegram。同一个数据库只启动一个机器人进程，不能与其他服务争用相同 Token 的更新。若之前配置过 Webhook，worker 会提示先在原服务停用，不会擅自删除。

需要代理时配置 `TELEGRAM_PROXY_URL=http://127.0.0.1:7890`。HTTP 代理必须能连通 Telegram；此项不作用于 AI / 汇率接口。

更新处理、草稿确认、账目写入及待发回复放在数据库事务中。重复 Telegram 更新或重复确认不会重复入账。回复使用持久队列重试；网络故障时记账提交不会回滚，极端断线时回复可能重复，但账目保持防重。

相关接口参考 [Telegram Bot API](https://core.telegram.org/bots/api)。

## Docker 部署

推荐直接使用 GitHub Actions 构建的 GHCR 镜像：

```sh
docker pull ghcr.io/meowapi/team-ledger:latest
cp .env.example .env
# 编辑 .env
docker compose pull
docker compose up -d --no-build
# 配置机器人后
docker compose --profile telegram up -d --no-build
```

Web 和 bot 使用同一镜像，数据通过命名卷持久化。要固定到某个版本，在 `.env` 中设置 `LEDGER_IMAGE=ghcr.io/meowapi/team-ledger:版本号`，再执行 `docker compose pull` 和 `docker compose up -d --no-build`。

也可从源码自行构建：

```sh
cp .env.example .env
# 编辑 .env
docker compose up -d --build
# 配置了机器人后，额外启动 bot
docker compose --profile telegram up -d --build
```

Web 默认只映射宿主机 `127.0.0.1:8765`。通过反向代理提供团队访问时，设置：

```dotenv
PUBLIC_URL=https://你的记账域名
COOKIE_SECURE=true
```

使用 HTTPS 反向代理到 `127.0.0.1:8765`。先通过本机 / SSH 隧道完成首个账号初始化，再开放域名访问，避免首次初始化页面被别人抢先使用。不要直接公网暴露尚未初始化的实例。

Docker 的 Web 和 bot 共用 `ledger-data` 命名卷。数据库适合单台服务器上的小团队，不要放到 NFS 或多主机同时写入。

GitHub Actions 自动运行账务测试、构建并启动 AMD64 容器、检查健康接口和初始空账本，再发布 AMD64 / ARM64 双架构镜像。发布后还会在无登录凭据的环境验证多架构清单和匿名拉取。ARM64 在构建时通过 QEMU 模拟，不包含 ARM64 运行验证。

### 自动发布规则

- 推送 `main`：发布 `latest`、`main` 和完整提交 SHA 标签。
- 推送 `v1.2.3` 这样的版本标签：发布 `1.2.3`、`1.2` 和提交 SHA 标签。
- Pull Request：只运行测试，不发布镜像。
- 可在 Actions 的「Test and publish Docker image」中手动运行。
- 使用仓库自带的 `GITHUB_TOKEN` 发布 GHCR，无需额外填写 Docker Hub 密钥。

镜像地址：`ghcr.io/meowapi/team-ledger`。构建状态和镜像摘要见 [GitHub Actions](https://github.com/MeowAPI/team-ledger/actions/workflows/docker-publish.yml)。

## 保存与备份

默认数据在 `data/`：`ledger.sqlite3`、相关 SQLite WAL 文件，以及 `receipts/`。可用 `DATA_DIR` 指定绝对目录。运行期间 SQLite 数据库与凭证都需要保留。

最简单的完整备份：暂时停止 Web 与 bot，复制整个数据目录或 Docker 命名卷，再恢复运行。恢复时一并恢复数据库和凭证。`.env` 中的密钥请单独安全保存，CSV 不能替代完整数据库备份。
